# The critical suite: the few tests whose failure would mean a broken rule or a broken demo.
#
# CI runs only these (`uv run pytest -m critical`, well under a minute). The complete suite
# (`uv run pytest`, about 4 minutes) is a local job and must pass before a push or a merge.
# tests/conftest.py reads this file and gives every test it names the `critical` marker; no test
# file carries a decorator for it.
#
# Format: one pytest node id per line. An entry names one case (file::test[case]), a test with all
# its cases (file::test), a class (file::TestClass) or a whole file. Blank lines and lines that
# start with # are ignored. Each group below is headed "# [n] ..." with n from 1 to 15; those are
# the fifteen lines of what "critical" means: 1 to 7 are rules that must never regress (the
# product rules of CLAUDE.md), 8 to 15 are what makes the demo work. Prefer one test that runs the
# real pipeline over a narrow unit test, and one case of a parametrised table over the whole table.
#
# To add a test: find its id with `uv run pytest --collect-only -q <path>`, add it under the
# heading it protects, run `uv run pytest -m critical -q`. A test that is not listed here still
# runs in the complete suite. Never list a test marked `live`. tests/foundation/test_critical_suite.py
# fails if an entry names no test (a renamed test, a changed case id), if a critical test is also
# marked live, if a heading has no test or if the count passes its ceiling (raise it on purpose).
